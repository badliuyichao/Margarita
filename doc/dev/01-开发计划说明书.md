## 1. 项目概述

**项目名称**：藏珠 (Margarita)

**项目目标**：开发一款跨平台桌面应用（Windows/macOS），帮助用户管理个人实物资产，量化拥有成本，通过折旧、闲置分析和消费决策辅助，培养理性消费习惯。

**核心功能模块**：物品管理、品类/空间管理、使用打卡、时间线、仪表盘、闲置清单、后悔榜、愿望清单、不买计算器、设置与数据管理。

**技术栈**：Tauri 2.x + React 18/TypeScript + Rust + SQLite。

**V1.0 范围**：完成全部 P0 功能，实现直线折旧法，支持三语国际化，本地优先存储。

## 2. 团队规划

### 2.1 团队组成

推荐组建一个 **5 人核心团队**，角色职责如下：

| 角色 | 代号 | 人数 | 职责 |
| :--- | :--- | :--- | :--- |
| **产品负责人** | PO | 1 | 需求优先级确定、项目进度把控、跨角色沟通、验收交付物、对外发布协调 |
| **UX/UI 设计师** | UX | 1 | 高保真设计稿、交互原型、视觉资源输出、国际化样式适配 |
| **前端开发工程师** | FE | 1 | React 组件开发、状态管理、IPC 调用封装、国际化实现、前端自动化测试 |
| **后端开发工程师** | BE | 1 | 数据库设计与实现、Tauri 命令开发、引擎算法实现、备份恢复、后端自动化测试 |
| **测试工程师** | QA | 1 | 测试策略制定、用例设计、自动化测试脚本编写、手动测试执行、CI/CD 管道维护 |

> 若团队规模受限，可采用最小配置 **3 人**：PO 兼任 UX，FE 兼任 QA，BE 独立。但为保证质量，5 人并行效率最高。

### 2.2 角色协作关系

- **PO** 与 **UX** 紧密配合完成产品设计，产出 PDD 中的高保真原型。
- **FE** 与 **BE** 通过接口契约（Tauri 命令入参/出参）并行开发，前端使用 mock 数据先行，后端完成后联调。
- **QA** 自项目启动即参与，编写与审查测试用例，开发完成后执行测试并反馈。
- 全员参与每日站会（10 分钟）同步进度与阻塞，每周一次周会复盘进度。

## 5. 团队协作机制

- **每日站会**：10 分钟，同步昨日进展、今日计划、阻塞点。
- **每周周会**：PO 主持，回顾里程碑进度，调整优先级，识别风险。
- **接口契约**：BE 完成命令定义后，立即输出 TypeScript 类型声明文件，FE 据此进行 mock 开发。
- **代码评审**：所有 PR 需至少一人 review 后才可合并，重点检查业务逻辑和测试覆盖。
- **设计评审**：UX 完成关键页面后，PO、FE、BE 共同评审可实现性与用户体验。
